# The GEN step for Phase2: what changes in ME, PS, MPI, Had, Decay and GenJet

`runCMSDrivers_mcPhase2_BBbar_SIM.sh` needs a step 1 (GEN) file produced with the Phase2 settings, so it
calls `runCMSDrivers_mc2024_BBbar_GEN.sh` with the overrides `CONDITIONS=auto:phase2_realistic_T33
ERA=Phase2C17I13M9 GEOMETRY=ExtendedRun4D110 BEAMSPOT=DBrealisticHLLHC COMENERGY=14000` (stage
`ME_PS_MPI_Had_Decay`, output `GEN_Phase2/`). This note states exactly what that changes in the generator
stages. The short answer: the generator *physics* is modified in one place only, the centre-of-mass energy
(13.6 TeV -> 14 TeV), which enters through the matrix element and, marginally, through the MPI regulator;
the parton shower, hadronisation, decay and jet-clustering settings are byte-identical. The second real
change is not a generator setting at all: the vertex smearing (`VtxSmeared`), which runs in the GEN step
after Pythia, uses the HL-LHC beam model instead of the 2024 beamspot. Era, global tag and geometry change
the process bookkeeping but not a single module of the generation path.

Evidence: `edmConfigDump` of `GEN/step1_GEN_ME_PS_MPI_Had_Decay_cfg.py` (2024) and
`GEN_Phase2/step1_GEN_ME_PS_MPI_Had_Decay_cfg.py` (Phase2) differ, inside the modules of
`generation_step = ProductionFilterSequence + pgen`, only in `generator.comEnergy` and in the `VtxSmeared`
module; `generatorSmeared`, `genParticles`, `genParticlesForJets`, `ak4GenJets`, `ak4GenJetsNoNu`,
`ak8GenJets`, `genMetTrue` and the `pgen` sequence are identical. Everything else in the dump diff
(pixel digitiser constants, ECAL digi flags, event-content keep statements, extra random-engine seeds) belongs
to modules that are loaded by the era but are not in any path of the GEN job.

## The stages and what touches them

The GEN script builds every stage from the same fragment (`BBbar_14TeV_TuneCP5_cfi.py`: Pythia8,
`HardQCD:qqbar2bbbar`, tune CP5, `PhaseSpace:pTHatMin = 100`) and switches Pythia steps off with
`--customise_commands` (ISR/FSR, MPI, HadronLevel:Hadronize, HadronLevel:Decay); the GenJet stage is a
separate step 2 on the full-event file. The Phase2 run applies the same switches, so the stages are the same
physics steps, in the same order, with the following differences:

| stage | Pythia / CMSSW step | changed for Phase2? | what changes |
|-------|---------------------|---------------------|--------------|
| `ME` | hard process `q qbar -> b bbar`, pTHat > 100 GeV, PDF NNPDF3.1 (CP5) | **yes, com energy** | `comEnergy` 13600 -> 14000 GeV: the momentum fractions x1 x2 = s_hat / s needed for a given hard-scattering kinematics are 2.9 % smaller (x ~ 1/sqrt(s)), so the parton luminosity and the cross section above the pTHat cut rise by a few per cent and the pTHat spectrum gets slightly harder. The b-quark kinematics and the colour flow are generated by the same matrix element. |
| `ME_PS` | + ISR and FSR (`PartonLevel:ISR/FSR`) | no setting | the showers evolve from the ME scale with the same tune parameters (`SpaceShower`, `TimeShower` alpha_s and cut-offs of CP5); they only see the harder / slightly different ME kinematics. |
| `ME_PS_MPI` | + multiparton interactions (`PartonLevel:MPI`) | **marginally, com energy** | the MPI regulator is the only tune parameter with an explicit energy dependence: pT0 = pT0Ref (sqrt(s)/ecmRef)^ecmPow with pT0Ref = 1.41 GeV, ecmRef = 7000 GeV, ecmPow = 0.03344 (CP5), i.e. pT0 = 1.4417 GeV at 13.6 TeV and 1.4431 GeV at 14 TeV, 0.1 % more; the MPI cross section itself grows with the beam energy, so the underlying event is slightly busier (few per cent more MPI activity). |
| `ME_PS_MPI_Had` | + string fragmentation (`HadronLevel:Hadronize`) | no | same Lund parameters, same colour reconnection (CP5). |
| `ME_PS_MPI_Had_Decay` | + hadron decays (`HadronLevel:Decay`) | no | same decay tables and the same CMSSW `pythia8CommonSettings` (tau0Max = 10 mm, i.e. the same list of particles left stable for Geant4: K0S, Lambda ... decay in Geant4, not in Pythia). |
| `..._GenJet` | step 2 `GENJET`: `genParticlesForJets` + anti-kT 0.4 / 0.8 | no | identical producers (the GEN step's own `genJetMET` sequence is also identical). |
| all stages | `VtxSmeared` -> `generatorSmeared` (after the generator, inside `pgen`) | **yes, beam model** | see below. `genParticles` is built from `generatorSmeared`, so the production vertices in every stage file carry the new smearing; the generator kinematics are untouched by it. |

In other words, a Phase2 stage file holds the same Pythia event type as its 2024 counterpart; comparing the
two is a 13.6 vs 14 TeV comparison of the matrix element plus a different luminous region.

## Vertex smearing: the one Phase2-specific module of the GEN step

cmsDriver puts the vertex smearing into the GEN step (`pgen` contains `VertexSmearing`, the module chosen by
`--beamspot`); the `--beamspot` of the SIM step is inert, which is why the Phase2 SIM script cannot simply
reuse the 2024 GEN file for a faithful Phase2 chain. Both choices read their parameters from the global tag
(`readDB = True`), so the global tag enters the GEN step only here:

| | 2024 (`DBrealistic`) | Phase2 (`DBrealisticHLLHC`) |
|---|---|---|
| module | `BetafuncEvtVtxGenerator` (`VtxSmearedRealistic_cfi`) | `HLLHCEvtVtxGenerator` (`VtxSmearedRealisticHLLHC_cfi`) |
| record / tag | `SimBeamSpotObjectsRcd`, `SimBeamSpot_Realistic25ns13p6TeVEarly2024CollisionVtxSmearingParameters_v1_mc` (GT `150X_mcRun3_2024_realistic_v2`) | `SimBeamSpotHLLHCObjectsRcd`, `SimBeamSpotHLLHCObjects_z4p3cm_t193ns_14TeV_nominal_mc_v1` (GT `150X_mcRun4_realistic_v1`) |
| model | Gaussian z (SigmaZ) and a beta-function transverse profile around a measured centre | two 7 TeV bunches with crossing angle, crab cavities and finite bunch length; the luminous region is computed from the overlap, in space and time |
| parameters (payload) | X0 = 0.0285 cm, Y0 = -0.0166 cm, Z0 = 0.416 cm, SigmaZ = 3.6 cm, beta* = 30 cm, emittance = 5.725e-8 cm (sigma_xy = sqrt(emittance beta*) = 13 um) | centre (0, 0, 0), crossing angle 510 urad, crabbing angle 380 urad, beta* = 0.2 m in both planes, normalised emittance 2.5 / 2.05 um, bunch length 9 cm, 400 MHz crab RF; luminous region sigma_z = 4.3 cm, sigma_t = 193 ps (tag name), transverse a few um |
| consequence | PV spread +-3.6 cm around z = 0.42 cm, displaced by 0.3 mm in x, y | PV spread +-4.3 cm around the origin, with a per-event collision time (relevant for the Phase2 MTD timing layers; the SimAnalyzer does not draw it) |

The single events of the test runs illustrate the different centres: PV = (0.028, -0.017, 3.11) cm in the
2024 sample and (0.001, -0.0002, 0.55) cm in the Phase2 sample (page 1 of the SimAnalyzer logs).

## Settings that change nothing in the generator path

- **Era** `Phase2C17I13M9` instead of `Run3_2024`: no era modifier touches `generator`, `VtxSmeared`,
  `genParticles` or the GenJet producers (dump diff above). It matters only once the file is read by the
  Phase2 SIM step (and, in the GEN job, it adds Phase2 modules that are never run).
- **Global tag** `auto:phase2_realistic_T33` (= `150X_mcRun4_realistic_v1` + Phase2 tracker alignment and
  pixel tags): in the GEN step only the beamspot record is read.
- **Geometry** `ExtendedRun4D110` instead of `DB:Extended`: loaded (`GeometryExtendedRun4D110Reco_cff`) but
  not used by any module of the GEN path; it is there so that the configuration is the Phase2 one that the
  SIM step continues.
- **Random seeds**: the same default seeds, but the 14 TeV sampling and the different smearing make the
  Phase2 events different from the 2024 ones, not a re-smearing of the same events.

## Practical consequences

- `GEN_Phase2/step1_GEN_ME_PS_MPI_Had_Decay_out.root` is the Phase2 input; it is generated automatically by
  `runCMSDrivers_mcPhase2_BBbar_SIM.sh` if missing. To produce the other generator stages, or the GenJet
  stage, at 14 TeV with the HL-LHC luminous region:

      CONDITIONS=auto:phase2_realistic_T33 ERA=Phase2C17I13M9 GEOMETRY=ExtendedRun4D110 \
      BEAMSPOT=DBrealisticHLLHC COMENERGY=14000 OUTDIR=GEN_Phase2 EVENTS=10 ./runCMSDrivers_mc2024_BBbar_GEN.sh

- `INPUT=GEN/step1_GEN_ME_PS_MPI_Had_Decay_out.root ./runCMSDrivers_mcPhase2_BBbar_SIM.sh` runs the Phase2
  detector on the 2024 events: same Pythia events as the 2024 SIM stages (13.6 TeV, 2024 luminous region,
  PV offset by 0.3 mm and spread +-3.6 cm). For the eta-phi maps of SimAnalyzer the difference between the
  two luminous regions is negligible (a few cm along z change eta at the per-mille level); it is the
  cleanest way to compare the 2024 and Phase2 detectors particle by particle.
- The GenPartAnalyzer pages of a Phase2 sample (the generator-record pages that precede the SIM pages) are
  therefore read exactly as for 2024: stage 1 is the ME, 2 the showered partons, 3 with MPI, 4 the hadrons,
  5 the stable final state, with no Phase2-specific content.
