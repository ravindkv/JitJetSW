# Chapter 03, MnM: technical companion

Matching and merging. The event of the book is a leading-order 2 -> 2 process (`q qbar -> b bbar`) generated by Pythia8
alone, with no external matrix-element generator, no LHE input and no extra-jet samples, so there is nothing to match
or merge: the stage is empty. The script `test/03_MnM/run_03_MnM.sh` runs no `cmsDriver.py` and no `cmsRun`. It checks
in the configuration and in the Pythia8 banner of chapter 02 that no matching or merging is configured, counts the
outgoing partons of the hard process with FWLite, writes the check to `test/03_MnM/out/mnm_03_MnM.log`, and links the
output of chapter 02 as the output of this chapter (Rule E). Every command below is run from `test/` of an initialized
`CMSSW_15_0_5` (`cd CMSSW_15_0_5/src && cmsenv && cd JitJetSW/Journey/test`).

## 1. The cmsDriver.py commands

This chapter runs no `cmsDriver.py`. The command it checks is the one of chapter 02, taken from the header
(`# with command line options:`) of `test/02_PS/step1_GEN_02_PS_cfg.py` (line 5 of the file, quoted in
`test/03_MnM/out/mnm_03_MnM.log`):

```bash
cmsDriver.py Configuration/GenProduction/python/BBbar_14TeV_TuneCP5_cfi.py \
  --conditions auto:phase1_2024_realistic --era Run3_2024 --geometry DB:Extended --beamspot DBrealistic \
  -n 1 -s GEN --datatier GEN --eventcontent FEVTDEBUG --fileout file:step1_GEN_02_PS.root \
  --customise_commands "process.generator.comEnergy = cms.double(13600.0)\nprocess.generator.PythiaParameters.processParameters.extend(['PhaseSpace:pTHatMin = 100', 'PartonLevel:ISR = on', 'PartonLevel:FSR = on', 'PartonLevel:MPI = off', 'HadronLevel:all = off', 'HadronLevel:Hadronize = off', 'HadronLevel:Decay = off'])" \
  --python_filename 02_PS/step1_GEN_02_PS_cfg.py --no_exec
```

| argument | meaning |
|---|---|
| `Configuration/GenProduction/python/BBbar_14TeV_TuneCP5_cfi.py` | the generator fragment (symlinked by `jitjet_fragment` from `JitJetSW/Configuration/GenProduction/python/`): a `Pythia8ConcurrentGeneratorFilter` with `HardQCD:qqbar2bbbar = on`, `HardQCD:gg2bbbar = off`, tune CP5, `comEnergy = 14000` |
| `--conditions auto:phase1_2024_realistic` | the global tag (alignment, calibrations) of the 2024 MC |
| `--era Run3_2024` | the era: which detector configuration modifiers apply |
| `--geometry DB:Extended` | the geometry read from the database |
| `--beamspot DBrealistic` | the beam-spot (vertex smearing) parameters from the database |
| `-n 1` | one event |
| `-s GEN` | the step: generation only |
| `--datatier GEN --eventcontent FEVTDEBUG` | the data tier label and the output content (everything, `FEVTDEBUG`) |
| `--fileout file:step1_GEN_02_PS.root` | the output file (written in `test/02_PS/out/`, where `cmsRun` is executed) |
| `--customise_commands ...` | python appended to the configuration: the energy to 13.6 TeV, `pTHatMin` to 100 GeV, ISR and FSR on, MPI, hadronisation and decays off |
| `--python_filename ... --no_exec` | write the configuration and do not run it (the script runs `cmsRun` itself) |

What is absent from this command and from the fragment is what a matching or merging sample would have: the `LHE`
step (`-s LHE,GEN`), an `ExternalLHEProducer` with a gridpack, a `Pythia8HadronizerFilter` and a block of
`JetMatching:` (MLM, FxFx) or `Merging:` (CKKW-L) settings. For comparison, this is how the FxFx validation sample of
the release would be generated (not run by the book; the gridpack is on cvmfs, the step takes minutes and needs the
`run_generic_tarball_cvmfs.sh` environment; `--conditions` and `--era` are those of the 13 TeV fragment):

```bash
cmsDriver.py Configuration/Generator/python/TTbar012Jets_5f_NLO_FXFX_Madgraph_LHE_13TeV_cfi.py \
  --conditions auto:run2_mc --era Run2_2016 --beamspot Realistic25ns13TeV2016Collision \
  -n 10 -s LHE,GEN --datatier LHE,GEN --eventcontent LHE,RAWSIM --fileout file:ttbar012j_fxfx.root \
  --python_filename ttbar012j_fxfx_cfg.py --no_exec
```

## 3. The analyzer configs

No analyzer runs in this chapter: the event is not changed, so the GenPartAnalyzer pages and the ledger of chapter 02
(`test/02_PS/out/genPartAnalyzer_02_PS.pdf`, `genPartAnalyzer_02_PS_page-1.png`, `_page-2.png`,
`ledger_02_PS.txt`) are the pages and the ledger of this stage, and the .tex reuses
`test/02_PS/out/genPartAnalyzer_02_PS_page-2.png` as its display. What the script produces instead is the check,
`test/03_MnM/out/mnm_03_MnM.log`, made of three commands that can be run by hand:

```bash
# (1) the generator fragment and the Pythia8 parameters of chapter 02: is any matching / merging / LHE setting there?
grep -nE "processParameters|HardQCD|pTHatMin|PartonLevel|HadronLevel|Merging|JetMatching|LHE|UserHooks|ExternalDecays" \
  02_PS/step1_GEN_02_PS_cfg.py

# (2) the Pythia8 banner of chapter 02 lists every setting changed from its default: any Merging:, JetMatching, UserHooks?
grep -niE "Merging:|JetMatching|UserHooks" 02_PS/out/step1_GEN_02_PS.log || echo "none"

# (3) the outgoing partons of the hard process (Pythia8 status 23) of event 1:1:1, read with FWLite
python3 - 02_PS/out/step1_GEN_02_PS.root 1:1:1 <<'PY'
import sys
from DataFormats.FWLite import Events, Handle
h = Handle('std::vector<reco::GenParticle>')
for ev in Events(sys.argv[1]):
    a = ev.eventAuxiliary()
    if '%d:%d:%d' % (a.run(), a.luminosityBlock(), a.event()) != sys.argv[2]:
        continue
    ev.getByLabel('genParticles', h)
    out = [p for p in h.product() if p.status() == 23]
    print('   %d outgoing partons of the hard process: %s' % (len(out), ', '.join('pdg %d pT %.1f' % (p.pdgId(), p.pt()) for p in out)))
    break
PY
```

The first grep prints the configuration lines that contain one of the words (line numbers of
`02_PS/step1_GEN_02_PS_cfg.py`); the second prints nothing for this event (Pythia8 prints only the settings that differ
from their defaults, under "Settings (changes only)"); the third prints the two `b` quarks. To see the same thing in
the Pythia8 defaults: `JetMatching:merge` (master switch of MLM / FxFx) defaults to `off` and `Merging:Process`
(master switch of CKKW-L) defaults to `void` in `$PYTHIA8DATA/JetMatching.xml` and `$PYTHIA8DATA/CKKWLMerging.xml`
(`PYTHIA8DATA` is set by `cmsenv` to
`/cvmfs/cms.cern.ch/el9_amd64_gcc12/external/pythia8/311-62f197bacb831a8defc23e576ff6b2ab/share/Pythia8/xmldoc`), and
`GeneratorInterface/Pythia8Interface/plugins/Pythia8Hadronizer.cc` (lines 494-519 in the release) attaches the
matching or merging user hook only when one of the two is changed.
