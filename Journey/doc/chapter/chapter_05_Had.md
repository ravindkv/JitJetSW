# Chapter 05, Had: technical companion

Hadronisation of the ONE bbbar event (run 1, lumi 1, event 1): the configuration of chapter 04 with the Lund string
fragmentation switched on (`HadronLevel:Hadronize = on`) and the hadron decays still off (`HadronLevel:Decay = off`).
Script: `test/05_Had/run_05_Had.sh`; outputs in `test/05_Had/out/`. All commands below are run from `test/` of an
initialized CMSSW_15_0_5 (`cd CMSSW_15_0_5/src && cmsenv && cd JitJetSW/Journey/test`).

```bash
05_Had/run_05_Had.sh            # everything: cmsDriver.py, cmsRun GEN, GenPartAnalyzer, PNG pages, ledger
RUN=0 05_Had/run_05_Had.sh      # only write step1_GEN_05_Had_cfg.py
ANALYZE=0 05_Had/run_05_Had.sh  # GEN step only, no analyzer, no ledger
```

The script sources `common/jitjet_common.sh` and calls `gen_stage on on on on off 4 "hadronisation (Lund strings)"`
(ISR, FSR, MPI, Hadronize on; Decay off; 4 analyzer pages). It requires the output of chapter 04
(`04_MPI/out/step1_GEN_04_MPI.root`, Rule E) to exist, although the event is regenerated from scratch with the same seeds.

## 1. The cmsDriver.py commands

The one command of the chapter, as written by `run_driver` of `common/jitjet_common.sh` and recorded in the header
of `05_Had/step1_GEN_05_Had_cfg.py` ("with command line options") and in `05_Had/out/step1_GEN_05_Had_cfg.driver.log`:

```bash
cmsDriver.py Configuration/GenProduction/python/BBbar_14TeV_TuneCP5_cfi.py \
  --conditions auto:phase1_2024_realistic --era Run3_2024 --geometry DB:Extended --beamspot DBrealistic \
  -n 1 -s GEN --datatier GEN --eventcontent FEVTDEBUG --fileout file:step1_GEN_05_Had.root \
  --customise_commands "process.generator.comEnergy = cms.double(13600.0)
process.generator.PythiaParameters.processParameters.extend(['PhaseSpace:pTHatMin = 100', 'PartonLevel:ISR = on', 'PartonLevel:FSR = on', 'PartonLevel:MPI = on', 'HadronLevel:all = on', 'HadronLevel:Hadronize = on', 'HadronLevel:Decay = off'])" \
  --python_filename 05_Had/step1_GEN_05_Had_cfg.py --no_exec
```

| argument | meaning |
|---|---|
| `Configuration/GenProduction/python/BBbar_14TeV_TuneCP5_cfi.py` | the generator fragment: Pythia8 `HardQCD:qqbar2bbbar = on` (gg -> bbbar off), `PhaseSpace:pTHatMin = 30.`, tune CP5 (`pythia8CP5SettingsBlock`) and the CMS common settings (`pythia8CommonSettingsBlock`); the fragment lives in `JitJetSW/Configuration/GenProduction/python/` and is symlinked into `$CMSSW_BASE/src/Configuration/GenProduction/` by `jitjet_fragment`, because cmsDriver.py imports it as a python module |
| `--conditions auto:phase1_2024_realistic` | the global tag alias for the 2024 realistic MC conditions (resolved by `Configuration/AlCa/python/autoCond.py`); at GEN it fixes the beam spot and the particle table |
| `--era Run3_2024` | the era modifiers of the 2024 detector (`Configuration/Eras/python/Era_Run3_2024_cff.py`); no effect on the generator itself, kept identical in every chapter |
| `--geometry DB:Extended` | geometry from the database (needed by the loaded standard sequences, not used at GEN) |
| `--beamspot DBrealistic` | the vertex smearing `IOMC/EventVertexGenerators/python/VtxSmearedRealistic_cfi.py` with the beam spot of the global tag: `generatorSmeared` carries the smeared vertex |
| `-n 1` | one event: the book follows ONE event (`EVENTS=1`) |
| `-s GEN` | the step: generation only, the `pgen` sequence (generator, `genParticles`, generator jets, `genMetTrue`) |
| `--datatier GEN --eventcontent FEVTDEBUG` | data tier and event content of the output: FEVTDEBUG keeps everything the GEN step makes |
| `--fileout file:step1_GEN_05_Had.root` | the output file, written in `05_Had/out/` (cmsRun is executed there) |
| `--customise_commands "..."` | python appended at the end of the configuration: the centre-of-mass energy 13.6 TeV (the fragment says 14 TeV) and the Pythia8 switches of this chapter appended to `processParameters`, so that they override the fragment's `pTHatMin = 30.` and set the levels |
| `PhaseSpace:pTHatMin = 100` | the hard-process pT threshold of the book (`PTHATMIN=100`) |
| `PartonLevel:ISR/FSR/MPI = on` | initial-state and final-state showers and multiparton interactions on, as in chapter 04 |
| `HadronLevel:all = on`, `HadronLevel:Hadronize = on` | the hadron level runs, with the Lund string fragmentation: this is the switch of the chapter |
| `HadronLevel:Decay = off` | no hadron decays: the primary hadrons are the final state (chapter 06 turns this on) |
| `--python_filename ... --no_exec` | write the configuration to `05_Had/step1_GEN_05_Had_cfg.py` and do not run it (the script runs `cmsRun` itself) |

## 2. The cmsRun on the python config

```bash
cd 05_Had/out && cmsRun ../step1_GEN_05_Had_cfg.py > step1_GEN_05_Had.log 2>&1; cd ../..
```

Walk-through of `05_Had/step1_GEN_05_Had_cfg.py` (generated by cmsDriver.py; do not edit, re-run the script instead):

- `process = cms.Process('GEN', Run3_2024)`: the process name GEN with the 2024 era; the products of the file carry the
  process label `GEN` (the analyzer reads `genParticles::GEN`).
- `process.load(...)`: the standard sequences: `Services_cff` (random numbers), `pythiapdt_cfi` (the particle table),
  `MessageLogger`, `EventContent_cff`, `mixNoPU_cfi` (no pileup), geometry and magnetic field (not used at GEN),
  `Generator_cff` (defines `pgen`), `VtxSmearedRealistic_cfi`, `genFilterSummary_cff`, `EndOfProcess_cff`,
  `FrontierConditions_GlobalTag_cff`.
- `process.maxEvents.input = 1`, `process.source = cms.Source("EmptySource")`: no input file, the generator makes the event;
  the event id is run 1, lumi 1, event 1.
- `process.FEVTDEBUGoutput`: the `PoolOutputModule` writing `file:step1_GEN_05_Had.root` with the FEVTDEBUG event content,
  only for events passing `generation_step`.
- `process.GlobalTag = GlobalTag(process.GlobalTag, 'auto:phase1_2024_realistic', '')`: the conditions.
- `process.generator = cms.EDFilter("Pythia8ConcurrentGeneratorFilter", ...)`: the Pythia8 interface, with
  `comEnergy = 14000.0` (overridden below), `PythiaParameters` made of three blocks applied in the order of
  `parameterSets`: `pythia8CommonSettings` (8 lines, `Pythia8CommonSettings_cfi.py`), `pythia8CP5Settings` (21 lines,
  `MCTunes2017/PythiaCP5Settings_cfi.py`) and `processParameters` (the three lines of the fragment).
- `process.generation_step = cms.Path(process.pgen)` and the schedule `generation_step, genfiltersummary_step, endjob_step,
  FEVTDEBUGoutput_step`; the `ProductionFilterSequence` (the generator) is inserted first in every path.
- The customisation from the command line, at the end: `process.generator.comEnergy = cms.double(13600.0)` and the
  `processParameters.extend([...])` of section 1. Since Pythia8 reads the settings in order, the `PhaseSpace:pTHatMin = 100`
  appended here overrides the `30.` of the fragment (the log of Pythia8 confirms `PhaseSpace:pTHatMin | 100.00000`).
- `customiseEarlyDelete`: memory housekeeping, no physics.

What Pythia8 printed in `05_Had/out/step1_GEN_05_Had.log` (Pythia 8.311, LHAPDF 6.4.0, NNPDF31_nnlo_as_0118): the
"changes only" settings table (every setting that differs from the Pythia8 default; the hadronisation parameters are
not in it, see section 4), the hard process listing (`q qbar -> b bbar`, code 124), the MPI initialisation
(`sigmaNonDiffractive = 55.42 mb`, `pT0 = 1.44`), the info listing of the event (`Number of MPI = 32, ISR = 28, FSRproc = 64`)
and the cross section (`1.577e-07 mb`).

## 3. The analyzer configs

Run by `gen_stage` after the GEN step (`ANALYZE=1`), in `05_Had/out/` (`CONE_R=${CONE_R:-0.4}` in `run_05_Had.sh`,
as in chapters 02 and 04; `REGEN=0 ./05_Had/run_05_Had.sh` keeps the GEN file and redoes only these three steps, which
is how the pages with the cones were made on 13 November 2026, the GEN file unchanged, md5 `ec6ba12b...`):

```bash
cd 05_Had/out
cmsRun ../../common/genPartAnalyzer_cfg.py inputFiles=file:step1_GEN_05_Had.root outputFile=genPartAnalyzer_05_Had.root \
   maxEvents=1 eventsToProcess=1:1:1 maxStage=4 pdfFile=genPartAnalyzer_05_Had.pdf \
   sampleLabel="chapter 05_Had: hadronisation (Lund strings)|ISR on, FSR on, MPI on|Hadronize on, Decay off|pTHatMin 100 GeV, 13.6 TeV" \
   coneR=0.4 > genPartAnalyzer_05_Had.log 2>&1
pdftoppm -cropbox -r 110 -png genPartAnalyzer_05_Had.pdf genPartAnalyzer_05_Had_page
python3 ../../common/genLedger.py step1_GEN_05_Had.root --event 1:1:1 > ledger_05_Had.txt 2> ledger_05_Had.log
cd ../..
```

- `common/genPartAnalyzer_cfg.py` (plugin `GenPartAnalyzer`, `plugins/GenPartAnalyzer.cc`): one eta-phi page per
  generation stage up to `maxStage=4`: page 1 the hard process (the two b quarks, status 23), page 2 the parton shower
  (14 particles: the hard process and its shower), page 3 MPI and beam remnants (169 partons, status 62/63, the b quarks with primordial kT), page 4 the
  hadronisation (the 320 primary hadrons, the B- and B*+ matched to the b and bbar chains). Marker size ~ log pT, labels
  for pT > 5 GeV, particles beyond |eta| = 6 on the border. On every page the dashed cones Delta R < 0.4 around the two
  systems (`coneR=0.4`) with their pT, and an inset magnifying the fuller cone with the name and pT of the 12 hardest
  particles within 1.25 x 0.4 of its axis ("+N more" for the others); on page 4 the B- cone (9 hadrons, 114.4 GeV), the
  inset of figure 5.1. Pages 1-3 are those of chapter 04 (same parton level). Outputs: `genPartAnalyzer_05_Had.pdf` (4 pages),
  `genPartAnalyzer_05_Had_page-1..4.png` (110 dpi, cropbox), `genPartAnalyzer_05_Had.root` (the TH2 per stage) and
  `genPartAnalyzer_05_Had.log` (the b / bbar / net b+bbar pT per stage and the quark-to-hadron matching, section 4).
- `common/genLedger.py` (FWLite, no cmsRun): the record by status group, the hard process, the final state by kind and by
  region, and the cones Delta R < 0.4 around the last copies of the b and bbar quarks, written to `ledger_05_Had.txt`
  (section 4).
- The extra counts of section 4 (species, strings, b hadrons) are two short FWLite scripts given there; they read the
  same file and need only `cmsenv`.

# cones0506.py: the stable particles within Delta R < 0.6 of the two b hadrons, the stable descendants of each hadron
import sys, math
from DataFormats.FWLite import Events, Handle
def dR(a, b):
    d = abs(a.phi() - b.phi()); d = min(d, 2 * math.pi - d); return math.hypot(a.eta() - b.eta(), d)
h = Handle('std::vector<reco::GenParticle>')
f, iB, iBbar = sys.argv[1], int(sys.argv[2]), int(sys.argv[3])
for ev in Events(f):
    ev.getByLabel('genParticles', h); P = h.product()
    key = lambda p: (p.pdgId(), p.status(), round(p.energy(), 6), round(p.pz(), 6))
    idx = {key(p): i for i, p in enumerate(P)}
    def stable_desc(i, out):
        p = P[i]
        if p.status() == 1: out.add(i); return
        for j in range(p.numberOfDaughters()): stable_desc(idx[key(p.daughter(j))], out)
    for name, ib in (('b', iB), ('bbar', iBbar)):
        B = P[ib]; prod = set(); stable_desc(ib, prod)
        rows = sorted((dR(B, p), i, p) for i, p in enumerate(P) if p.status() == 1 and dR(B, p) < 0.6)
        for d, i, p in rows:
            print('%s [%4d] pdg %6d pt %7.3f dR %.3f %s' % (name, i, p.pdgId(), p.pt(), d, 'product' if i in prod else ''))
