# GenJet step (fastjet) after every generator stage, with GenJetAnalyzer plots

The GEN step of runCMSDrivers_mc2024_BBbar_GEN.sh already clusters jets: pgen (Configuration/StandardSequences/
Generator_cff.py) contains genJetMET, i.e. genParticlesForJets (status 1 genParticles) + FastjetJetProducer for
ak4GenJets, ak8GenJets, ak4GenJetsNoNu and ak8GenJetsNoNu, and every step1_GEN_<stage>_out.root holds them
(for the ME sample: two one-constituent jets, the b and the bbar; for ME_PS: the b jet collects the FSR gluons).
The clustering is now also an explicit step of the journey, so that it can be configured and followed on its own.

- Journey/python/genJet_cff.py: genJetSequence = the standard input selectors and anti-kT producers
  (R = 0.4 / 0.8, jet pT > 3 GeV), scheduled by cmsDriver.py as a USER step.
- Journey/test/runCMSDrivers_mc2024_BBbar_GEN.sh: sixth stage ME_PS_MPI_Had_Decay_GenJet (last in the default
  STAGES; the earlier stages are unchanged and do not cluster). It runs step 2 (process GENJET), generated by
  cmsDriver.py with `step2 --filein file:step1_GEN_ME_PS_MPI_Had_Decay_out.root -s USER:JitJetSW/Journey/
  genJet_cff.genJetSequence --processName GENJET -n -1 --datatier GEN --eventcontent FEVTDEBUG --outputCommands
  'drop *_ak4GenJets*_*_GEN,drop *_ak8GenJets*_*_GEN'` (same conditions, era and geometry as step 1), on the
  step 1 output of ME_PS_MPI_Had_Decay; if that file is missing (STAGES without the full stage) the full stage is
  run first. The GEN-process jets are dropped so that the stage file has exactly one set of jets, produced by that
  step. Then genJetAnalyzer_cfg.py runs on it with maxStage=5, so that, like the PDFs of the earlier stages, the
  PDF holds per event the five GenPartAnalyzer pages followed by the jet pages. Files:
  step2_GENJET_ME_PS_MPI_Had_Decay_GenJet_cfg.py (+ .driver.log), step2_GENJET_ME_PS_MPI_Had_Decay_GenJet_out.root
  (+ .log), genJetAnalyzer_ME_PS_MPI_Had_Decay_GenJet_out.pdf, .root (genPartAnalyzer and genJetAnalyzer
  directories), .log. New variables: JETPTMIN (jet pT threshold of the four producers, default 3 GeV, via
  --customise_commands), JETS (collections drawn by GenJetAnalyzer, default ak4GenJets,ak4GenJetsNoNu,ak8GenJets);
  ANALYZE=0 skips both analyzers, RUN=0 only writes the configs. The build check also rebuilds when
  JitJetSW.Journey.genJet_cff cannot be imported and a GenJet stage is requested.
- Journey/plugins/GenJetAnalyzer.cc: per jet collection and event, an eta-phi page with every jet as a circle of
  radius R (wrapped in phi, clipped to the frame), its constituents in the jet colour, unclustered status 1
  particles in grey, the hard-process b / bbar followed to their last same-flavour copy and matched to the nearest
  jet within R (red / blue), the quark directions as open stars, the response pT(jet)/pT(quark), the net
  b jet + bbar jet pT, Delta phi and dijet mass in the header, and the leading jets listed in the right panel.
  R, jetAlgorithm, jetPtMin and src are read from the producer ParameterSet via edm::parameterSet(provenance,
  processHistory), so the config needs only the collection names; the process name (GEN or GENJET) is printed.
  Constituents are mapped to genParticles indices through the constituent Ptr keys (fallback: nearest status 1
  particle). pdfFile / sampleLabel / multi-page handling as in GenPartAnalyzer. TFileService histograms per
  collection: nJets, jetPt, jetEta, nConstituents, etaPhiPt, ptBjet, ptBbarJet, ptNetBBbarJets, responseB.
- Journey/test/genJetAnalyzer_cfg.py: VarParsing options jets (comma-separated), maxStage (generator-record
  stages drawn by GenPartAnalyzer before the jet pages, default 5, 0 = none), etaMax, labelPtMin,
  printConstituents, pdfFile, sampleLabel; the output-name tags are cleared as in genPartAnalyzer_cfg.py. With
  maxStage > 0 the path is genPartAnalyzer + genPartPagesFirst (HLTBool, always true) + genJetAnalyzer: the
  framework orders the modules of a Path only across EDFilters (without the filter GenJetAnalyzer ran first and
  the pages came out shuffled), and the filter makes the stage pages of every event precede the jet pages.
- Journey/plugins/GenPartAnalyzer.cc and GenJetAnalyzer.cc: parameters openPdf / closePdf (default true). Two
  modules of one job can print into the same multi-page PDF (ROOT appends the pages of either canvas to the open
  file); genJetAnalyzer_cfg.py lets GenPartAnalyzer open it and GenJetAnalyzer close it in endJob.
- Journey/python/jitJet_cff.py: customiseJitJet handles the GENJET process (GenJourney with the four jet
  collections of that process, constituents as genParticles keys), so DUMP>0 covers step 2 as well.
- Journey/README.md: section on the GenJet step and GenJetAnalyzer.

Checked with EVENTS=2 for all six stages, and with STAGES=ME_PS_MPI_Had_Decay_GenJet alone (the full stage is
generated first) and RUN=0: the step 2 config runs, its output holds genParticles (GEN) and the four jet
collections (GENJET only), and the analyzer PDF has 8 pages per event (5 generator stages + 3 jet collections,
checked with ANALYZE_EVENTS=2: pages 1-5 stages of event 1, 6-8 its jets, 9-13 stages of event 2, 14-16 its jets). First event, ak4GenJets of the full
sample: b jet pT 117.8 (24 constituents, response 1.28 w.r.t. the status 71 quark), bbar jet 115.9, |net pT|
6.1 GeV, Delta phi 3.09, 27 jets, 239 of 634 status 1 particles clustered. Run by hand on the ME_PS step 1
file, the b quark (last copy, status 1, pT 47.0) -> jet pT 113.6 with 6 constituents (response 2.41, the FSR
gluons are back in the jet). DUMP=1 on the GENJET step prints the jets with their constituent keys.
